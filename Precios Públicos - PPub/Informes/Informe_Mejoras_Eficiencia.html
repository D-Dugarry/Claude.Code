Alto impacto

AE1 · Bloque de 6 diccionarios idéntico repetido literalmente (~110 líneas → ~20)

VBA_Moduls/M_132_Añadir_Núm_JIs_al_Inf.bas — líneas 86-198

El mismo bloque de creación de Scripting.Dictionary y volcado se repite 6 veces (una por columna JI), cambiando solo el nombre de columna origen/destino.

Antes (x6, con pequeñas variaciones)
Set RngJIs = Lo_BD.ListColumns(BD_JI_Emi_Adm).DataBodyRange.SpecialCells(xlCellTypeVisible)
Set DiccJIs = CreateObject("Scripting.Dictionary")
For Each Celda In RngJIs.Cells
    If Not IsEmpty(Celda.Value) Then DiccJIs(Celda.Value) = True
Next Celda
If DiccJIs.Count > 0 Then
    RwJI.Range(InfRec_JI_Emi_Adm).Value = Join(DiccJIs.Keys, ", ")
Else
    RwJI.Range(InfRec_JI_Emi_Adm).Value = "¿-?"
End If
Set DiccJIs = Nothing: Set RngJIs = Nothing
'- ... repetido idéntico x6 con otras columnas ...
Después
Dim ColsOrigen As Variant: ColsOrigen = Array(BD_JI_Emi_Adm, BD_JI_Emi_Acad, BD_AD_Emi_Adm, BD_AD_Emi_Acad, BD_JI_443_Adm, BD_JI_443_Acad)
Dim ColsDestino As Variant: ColsDestino = Array(InfRec_JI_Emi_Adm, InfRec_JI_Emi_Acad, InfRec_AD_Emi_Adm, InfRec_AD_Emi_Acad, InfRec_JI_443_Adm, InfRec_JI_443_Acad)
Dim DiccJIs As Object: Set DiccJIs = CreateObject("Scripting.Dictionary")   '- 1 sola vez, fuera del bucle
Dim k As Integer
For k = 0 To UBound(ColsOrigen)
    DiccJIs.RemoveAll
    Set RngJIs = Lo_BD.ListColumns(ColsOrigen(k)).DataBodyRange.SpecialCells(xlCellTypeVisible)
    For Each Celda In RngJIs.Cells
        If Not IsEmpty(Celda.Value) Then DiccJIs(Celda.Value) = True
    Next Celda
    RwJI.Range(ColsDestino(k)).Value = IIf(DiccJIs.Count > 0, Join(DiccJIs.Keys, ", "), "¿-?")

Impacto: reduce ~110 líneas a ~20 y evita crear el objeto COM Scripting.Dictionary repetidamente dentro de un bucle que ya está anidado dentro de otro (For F_Inf) — el late-binding COM tiene coste no despreciable si se repite miles de veces.

AE4 · Algoritmo de detección de duplicados copiado entre dos módulos

M_112_Manage_Duplicates.bas vs M_212_Mng_Duplicates_CAcadAnt.bas

Ambas rutinas recorren la tabla ordenada por referencia y marcan repeticiones con el mismo algoritmo, cambiando solo el nombre de columna de incidencia y qué se hace con los duplicados después.

Propuesta: extraer la fase de "identificación y marcado" a una función común Rut_Lo_Marcar_Duplicados(Lo_Data, ColRef, ColIncidencia) As Long reutilizada por ambos módulos, dejando en cada uno solo el tratamiento posterior específico. Evita que una corrección de bug en el criterio de comparación se aplique en un módulo y se olvide en el otro.

BE1 · Miles de escaneos completos de una tabla de ~176.000 filas

VBA_Moduls/M_600_Informe_EP_RSm.bas — líneas 95-170

Por cada combinación única de (Plan, C_Acad, AñoEmi) se itera 5 veces (tipos de recibo) y por cada una se ejecutan 6 SumIfs/CountIfs, cada uno recorriendo toda la tabla. Con cientos de combinaciones distintas, son miles de escaneos completos de la tabla más grande del libro — el cuello de botella más costoso de todo el proyecto auditado.

Antes (patrón repetido ~30 veces por combinación)
T_Emi_Tot = Application.SumIfs(Lo_EPs.ListColumns(BD_ImpRec).DataBodyRange, _
                                Lo_EPs.ListColumns(BD_Plan).DataBodyRange, Cod_Plan, _
                                Lo_EPs.ListColumns(BD_C_Acad).DataBodyRange, CAcad, _
                                Lo_EPs.ListColumns(BD_ACont_Emi).DataBodyRange, AñoEmi, ...)
' ... 5 más por cada combinación (Plan, C_Acad, AñoEmi, TipoRec) ...
Después — un único pase con Dictionary
Dim Arr As Variant: Arr = Lo_EPs.DataBodyRange.Value2    ' 1 sola lectura de bloque
Dim Dic As Object: Set Dic = CreateObject("Scripting.Dictionary")
Dim Clave As String, F As Long, V As Variant

For F = 1 To UBound(Arr, 1)
    If Arr(F, BD_ImpRec) > 0 Then
        Clave = Arr(F, BD_Plan) & "|" & Arr(F, BD_C_Acad) & "|" & Arr(F, BD_ACont_Emi) & "|" & _
                Arr(F, BD_Tipo_Rec) & "|" & Arr(F, BD_TIO_EP)
        If Not Dic.Exists(Clave) Then Dic.Add Clave, Array(0#, 0#, 0#, 0#, 0#, 0)
        V = Dic(Clave)
        V(0) = V(0) + Arr(F, BD_ImpRec)                                        ' T_Emi_Tot
        V(1) = V(1) + Arr(F, BD_ImpCob)                                        ' T_Cob_Tot
        V(2) = V(2) + Arr(F, BD_Rec_Imp_Adm)                                   ' T_Emi_Adm
        If Arr(F, BD_ImpCob) > 0 Then V(3) = V(3) + Arr(F, BD_Rec_Imp_Adm)    ' T_Cob_Adm
        If Arr(F, BD_RDT) <> "" Then V(4) = V(4) + Arr(F, BD_ImpCob)          ' T_RDT_Tot
        V(5) = V(5) + 1
        Dic(Clave) = V
    End If
Next F
' Recorrer el Dictionary (1 entrada por combinación real) para generar las filas de Lo_InfRSm

Impacto: pasa de "miles de escaneos de 176.000 filas" a un único recorrido de 176.000 filas más un recorrido del Dictionary — mejora esperada de varios órdenes de magnitud en tiempo de ejecución de este informe.

Propuestas de reprogramación de módulos completos

El diseño de fondo del proyecto —tabla de datos gobernada por una tabla de metadatos hermana (LoDefCol), rutinas genéricas Rut_Lo_* reutilizadas por todos los pipelines, patrón Call_Rut_.../Rut_...— es sólido y coherente con VBA de Excel. No recomiendo reescribir el framework desde cero. Sí hay 4 casos concretos donde una reprogramación específica está justificada:

1. M_193_Importar_Datos_Wb_mes_Ant.bas — reescritura completa

No es un caso de "parchear": mezcla al menos dos generaciones de intento (bloque nuevo con Dictionary/funciones inexistentes + bloque viejo comentado estilo M_118/M_215) y no compila (ver Informe de Bugs, A2). Propuesta: reescribirlo reutilizando el patrón merge-join ya probado en M_118/M_215 (ordenar por BD_Ref y recorrer en paralelo), con nombres de hoja/columna parametrizados —no hardcodeados como "Hoja_BD"— y gestión de errores que cierre siempre el libro origen abierto.

2. Extraer una función de merge-join genérica para M_118 / M_195 / M_215

Es exactamente el mismo algoritmo copiado 3 veces con nombres de variable ligeramente distintos — y es precisamente donde apareció el bug más grave del informe de Bugs (A1, el límite 1000 hardcodeado). Propuesta:

Function Rut_Lo_MergeJoin_PorRef(Lo_Origen As ListObject, Lo_Destino As ListObject, _
                                   ColRef As Integer, ColsOrigen() As Variant, ColsDestino() As Variant) As Long
    '- Recibe los arrays de columnas a copiar y devuelve el nº de "Found",
    '- centralizando el bucle en un solo sitio testeado.
End Function

Esto habría hecho imposible que el bug del 1000 hardcodeado se colara sin que los otros dos procesos lo detectaran igual; y si aparece otro bug similar, se corrige una vez para los tres procesos en vez de tres.

3. Unificar M_310-315 (LSace06/INSS) y M_410-415 (AE4) en un único framework de importación parametrizado

Son dos implementaciones paralelas del mismo concepto ("importar un Excel externo, limpiarlo, verterlo en BDatos") con soluciones distintas e inconsistentes: M_315 reconstruye el Imp. INSS con un emparejamiento fila-a-fila por Referencia (lento, y con el bug del Exit For, Informe de Bugs B6), mientras M_415 simplemente borra los recibos AE4 del curso y vuelca la tabla entera de nuevo — más simple, rápido y sin ese tipo de bug.

Propuesta: adoptar el patrón de M_415 también para M_310-315: tratar el Imp. INSS igual que el Imp. AE4 (borrar-y-reinsertar por curso académico), evitando el merge-join completo y su clase de bugs.

4. Reescribir M_602_Cierre_Contable_PLANES.bas como una única rutina parametrizada por "ciclos"

Los 4 bloques GoTo Ciclo_N casi idénticos ya han demostrado ser fuente directa de bugs críticos: el fallthrough (B3), el filtro de Anulados que hay que recordar poner en 4 sitios en vez de 1 (B2), la hoja de protección equivocada (B4).
