Nota sobre codificación: los ficheros .bas/.cls están en CP1252, no UTF-8. Los fragmentos de código citados aquí se han extraído con una pasada de lectura automática que en algún caso puntual puede mostrar un carácter acentuado distinto del real (p. ej. una ñ/ú mal representada en un nombre de variable secundario). El diagnóstico y la línea de bug no se ven afectados, pero antes de aplicar cualquier corrección directamente sobre VBA_Moduls\, verifica el byte real de esa línea concreta y edítala siempre con un script que preserve CP1252/CRLF — nunca con el Editor de texto plano ni herramientas UTF-8, tal como ya tienes documentado para este proyecto.

A1 · Límite de bucle hardcodeado a 1000 filas — pérdida silenciosa de datos

VBA_Moduls/M_195_Add_UXXIdata_in_BDatos.bas — línea 83

El bucle que traslada datos contables UXXI de Sht__BD_Ant a Sht__BD usa un literal 1000 en vez del bound real TF_BDant, que está calculado dos líneas antes y quedó comentado. Si el curso anterior tiene más de 1000 recibos —muy probable en una universidad—, todo lo que va después de la fila 1000 nunca se copia, sin ningún aviso.

Antes
For F_BDant = 1 To 1000 'TF_BDAnt
Después
For F_BDant = 1 To TF_BDant

Impacto: pérdida silenciosa de datos contables (coeficiente VRI/JIs/AD) en un proceso anual cuyo resultado alimenta directamente los Justificantes de Ingreso.

A3 · Rut_Off_Functions no fuerza EnableEvents, depende de un switch que puede estar desincronizado

VBA_Moduls/M_000_Ini_APP.bas — líneas 58-63

La desactivación de Application.EnableEvents está condicionada al valor del switch de hoja SW_Events en vez de fijarse siempre. Si el switch ya vale False por cualquier motivo previo (p. ej. tras el reseteo de variables que provoca un error VBA no controlado, ya documentado como riesgo conocido del proyecto), esta rutina no hace nada y los eventos quedan activos durante bucles masivos de import/depuración.

Antes
Sub Rut_Off_Functions()
Debug.Print "Rut_Off_Functions"
    Application.Calculation = xlCalculationManual
    Application.ScreenUpdating = False
    If Prog__APP.Range("SW_Events") Then
        Application.EnableEvents = False
        Prog__APP.Range("SW_Events") = False
    End If
End Sub
Después
Sub Rut_Off_Functions()
Debug.Print "Rut_Off_Functions"
    Application.Calculation = xlCalculationManual
    Application.ScreenUpdating = False
    Application.EnableEvents = False        '- Se fija SIEMPRE, sin depender del switch
    Prog__APP.Range("SW_Events") = False
End Sub

Impacto: Rut_On_Functions ya hace bien esto (ambas ramas fijan el valor); la asimetría entre ambas es la señal de que aquí falta el mismo cuidado.

A6 · Conversión de fecha por recorte de cadena, frágil ante configuración regional

Si el formato regional de Windows produce d/m/aaaa (por ejemplo, al cambiar de ordenador casa/trabajo, cada uno con su configuración regional), el criterio de filtro queda corrupto.

Después
Dim FechCierreCriteria As String
FechCierreCriteria = Format(CDate(Prog__APP.Range("APP_FechCierreCont").Value2), "mm\/dd\/yyyy")
.Range.AutoFilter Field:=BD_FCob, Criteria1:=">" & FechCierreCriteria

Sospecha a confirmar: si el formato de la celda APP_FechCierreCont está garantizado siempre con ceros, el bug hoy es solo latente — pero el patrón es frágil y debería corregirse igual, dado que decide qué recibos se borran.
